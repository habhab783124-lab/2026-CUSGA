# 塔防玩法重设计规范
Version: 1.4.1
Updated: 2026-04-27
Status: 已确认，作为当前后续开发基线

## 1. 地图中应长期存在的对象
- 防御塔
- 继电器
- 废料
- 剩余生命值
- 敌军
- 敌军路径
- 可放置建筑的空地
- 地图周边场景建筑
- 地图内场景建筑
- 出怪口旗帜
- 防御点旗帜

## 2. 地图结构
- 一张地图至少有 2 个出怪口。
- 出怪口通过路径通向防御点。
- 当前通常只有 1 个防御点，但后续设计必须允许扩展到多个。
- 战斗区域只分三类：
  - 路径
  - 空地
  - 地图内场景建筑
- 只有空地允许放置继电器与防御塔。
- 当前工程层面，空地建造区已允许通过多个 `Collider2D` 组合成不规则形状，而不再只依赖单个矩形区域。

## 3. 胜负与资源
- 玩家开局拥有一定量废料。
- 敌人死亡后自动奖励废料。
- 废料当前用于：
  - 放置防御塔
  - 升级防御塔
  - 升级继电器
- 继电器放置免费。
- 敌人突破防御点后按敌人设定扣除剩余生命值。
- 生命值归零时游戏失败。

## 4. 继电器系统
- 继电器本身不耗电，只负责供电。
- 继电器可以自由放在全场空地上。
- 一局内继电器数量受地图上限限制。
- 继电器升级消耗废料。
- 继电器升级后供电量增加，供电范围保持不变。
- 防御塔只能放在继电器供电范围内。
- 每次发生以下任一事件后，都要重新执行完整供电判定：
  - 防御塔放置
  - 防御塔升级
  - 防御塔铲除
  - 继电器放置
  - 继电器升级
  - 继电器铲除

## 5. 编号机制
- 防御塔和继电器各自维护独立编号序列。
- 初始从 `1` 到 `100`，数字越小优先级越高。
- 放置时取走当前最小可用编号。
- 当前设计基线是不回收编号。
- 编号的意义主要是供电分配优先级，而不是显示用途。

## 6. 供电判定原则
- 对每个继电器，按其供电范围内防御塔的编号从小到大尝试分配供电。
- 供电量足够则该塔工作，并扣除对应耗电。
- 供电量不足时，该塔以及后续未判定塔都不工作。
- 如果一座塔位于多个继电器覆盖范围内：
  - 最终由编号更小的那个继电器供电
  - 其余失去这座塔的继电器要重新结算
- 断电塔保留在场上，但停止工作。
- 防御塔升级前必须先校验升级后供电是否仍然合法。
- 若升级后会导致供电不足，则应阻止升级并提示用户。

## 7. 当前塔类型
### 继电器
- 放置免费
- 升级消耗废料
- 只负责供电

### 单体攻击塔
- 单次攻击一个敌人
- 当前同时临时承担“穿甲有效伤害”的角色

### 减速塔
- 对范围内所有敌人减速
- 当前保留伤害字段，但初版伤害可为 `0`
- 当前也承担“探测隐身敌人”的角色

### 炸弹塔
- 向目标点投掷炸弹
- 炸弹有飞行时间
- 落点爆炸造成小范围伤害

## 8. 当前敌人目录
- 拾荒者
  - 低血、中速、无甲，基础杂兵
- 狗 / 狼
  - 低血、超高速度、无甲，忽略减速效果
- 旗帜拾荒者
  - 较高血、低速、轻甲，会给周围友军套固定护盾
- 机械师
  - 中血、低速、轻甲，会修理附近机械单位
- 重甲机械兵
  - 高血、低速、重甲，非穿甲伤害大幅削弱
- 隐身人
  - 低血、高速，首次受到直接伤害后进入短暂隐身，可被减速塔探测
- 憎恶
  - 极高血、低速、无甲，死亡后分裂成两个小拾荒者
- 小拾荒者
  - 低血、中速、无甲，分裂产物，无废料奖励

## 9. 当前实现约定
- 敌人静态属性主链读取 `EnemyCatalogAsset`。
- 波次主链读取 `WaveCatalogAsset` 与每关独立 `WaveCatalog_LevelXX.asset`。
- 当前波次作者工作流默认是“Scene 做地图、WaveCatalog 资产做波次”，不再继续把旧组件内数组当成主链。
- 三类战斗塔共用 `DefenseTower`，但使用独立运行时 prefab。
- 敌人当前采用：
  - 基础壳：`Enemy`
  - 特殊机制模块：`EnemyStealthModule / EnemyShieldAuraModule / EnemyRepairModule / EnemySplitOnDeathModule`
- 这些模块支持：
  - 目录默认值
  - prefab 本地覆盖值
- 路径 / 出怪口 / 防御点当前支持程序化占位表现与作者自接管根节点两种模式。

## 10. 当前工程约束
- 地图和关卡后续主要由用户自己在 Unity Scene 视图中制作。
- 地图、路径、出怪口、防御点、UI、Prefab 引用优先通过场景与 Inspector 显式维护。
- 当前美术资源视为原型占位资源。
- 项目必须持续保持便于替换美术资源的状态。
