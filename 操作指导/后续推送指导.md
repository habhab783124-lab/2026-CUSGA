# 后续推送指导（Unity 项目协作版）

你已经完成过一次推送，后续可以按这个标准流程继续开发、提交、推送和发起 PR。

## 一、先确认当前仓库状态

```bash
cd "E:\\UNITY\\Unity Projects\\My project\\2026-CUSGA"
git status --short --branch
```

建议输出包含：
- 当前分支名
- 是否有未跟踪文件
- 是否有未提交修改

---

## 二、日常开发分支策略

推荐永远不要直接在 `main` 上改。

1. 从 `main` 新建功能分支

```bash
git checkout main
git pull origin main
git checkout -b feature/你的功能名
```

2. 只做与你本次任务相关的修改

3. 提交时按功能点分 commit（可选）

```bash
git add 你改的文件
git commit -m "feat: 描述具体功能"
```

---

## 三、已完成开发后的标准提交步骤

以你这次已经完成的流程为模板：

### 1）确认分支

```bash
git branch --show-current
```

应显示你现在的开发分支，例如：

- `feature/player-dialogue-controller-demo`

### 2）查看改动

```bash
git status --short --branch
```

### 3）添加并提交

```bash
git add Assets/DialogueManager.cs \
        Assets/IInteractable.cs \
        Assets/NPCInteractable.cs \
        Assets/PlayerController.cs \
        Assets/PlayerMovement.cs \
        Assets/TypewriterEffect.cs \
        "操作指导/GlobalDialogueUsageGuide.txt" \
        "操作指导/PlayerControllerUsageGuide.txt" \
        "操作指导/对话demo操作指导.md"

git commit -m "feat: add global dialogue manager and player interaction controller demo"
```

> 如果你这次只改了其他文件，把 `git add` 换成你本次实际改动。

### 4）推送到远端新分支

```bash
git push -u origin feature/player-dialogue-controller-demo
```

`-u` 的作用是把本地分支和远端同名分支绑定，后面直接用 `git push` / `git pull` 都会自动匹配。

---

## 四、后续继续改动（同一分支）

后续有新改动时，按“继续提交”流程：

```bash
git status --short --branch
# 修改文件
git add <文件>
git commit -m "feat/fix: 描述本次增量"
git push
```

如果这个分支是第一次推送后的后续提交，`git push` 会自动推到同一个远端分支。

## 五、多人协作常见场景

### 场景 A：本地落后于远端

```bash
git checkout feature/player-dialogue-controller-demo
git pull --rebase origin main
```

> 先把你的分支和最新 `main` 同步，再继续开发，能减少后续冲突。

### 场景 B：分支名填错导致推送失败

之前你遇到的报错：

```bash
error: src refspec xxx does not match any
```

常见原因：本地没有该分支。先 `git branch --show-current` 看当前分支名，再 `git push` 用**当前分支名**。

### 场景 C：你只是想把本地分支映射到不同远端名

```bash
git push -u origin 本地分支名:远端分支名
```

示例：

```bash
git push -u origin feature/player-dialogue-controller-demo:feature/dialogue-npc-controller
```

## 六、合并到主分支的建议流程（Pull Request）

1. 推送成功后，GitHub 页面会出现 `Compare & pull request`。
2. 标题建议：
   - `feat: add global dialogue manager and player interaction controller demo`
3. 描述内容建议包含：
   - 变更文件
   - 关键功能（移动、动画、NPC 交互、对话管理）
   - 是否有测试或运行步骤
4. 指定 Review 人，提交 PR。

## 九、常见错误速查

- `nothing added to commit but untracked files present`
  - 只需 `git add` 后再 `git commit`
- `src refspec ... does not match any`
  - 推送命令里的分支名和本地分支名不一致
- `fatal: not a git repository`
  - 当前路径不对，先 `cd` 到仓库根目录
